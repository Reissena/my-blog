### 校园新闻管理系统 · 毕业设计 · 大学期间

**技术栈**：Python + Django（Django REST Framework）／ Vue 3 + Vite

大学期间做的毕业设计：一个前后端分离的校园新闻系统 —— 起因是校园新闻原来靠人工编辑、邮件或者单一后台发布，
更新不及时、分类乱、也没有师生互动，所以后端只出 JSON 接口、前端单独做成单页应用，
把「发布 → 审核 → 浏览 → 收藏评论 → 后台管理」整条链路做通，另外还加了视频点播、论坛和投票。
下面写的是**这份毕设代码里实际有什么**（后端 19 个 `.py` 文件、1845 行 Python；前端 31 个页面组件）：

- **两端怎么分**：后端是 Django + REST Framework，用 `DefaultRouter` 挂了 users / categories / news /
comments / favorites / logs / videos / forum / polls / messages 十组接口，**没有用 Django 自带的 admin**，
管理后台是自己写在前端里的；前端是另一个 Vite 项目，axios 统一请求 `/api`，登录态存在 Pinia 里，
路由守卫按角色拦 `/admin` 和 `/editor`，开发时由 Vite 把 `/api` 和 `/media` 代理到后端的 8000 端口。
- **登录与权限**：JWT 是自己写的（PyJWT、HS256、7 天有效期，token 放在 `Authorization: Bearer` 请求头里），
角色分管理员 / 新闻编辑 / 普通用户三种，接口按角色决定放不放行。
- **新闻的流转**：草稿 → 待审核 → 已发布，另外还有「已退回」「已拒绝」两种带原因的终态；
编辑只看得到自己发的稿子，管理员审核时可以通过、退回、拒绝 —— **退回必须填修改意见**，
编辑那边能看到意见、改完再重新提交；发布之后还能置顶和推荐。
- **浏览与搜索**：列表按「置顶优先 + 时间倒序」排、每页 10 条，支持按分类筛选、按标题 / 正文 / 标签搜索；
详情页每打开一次浏览量 +1，另有两个接口分别给出「热门新闻」（浏览量前 10）和「推荐新闻」。
- **评论与收藏**：评论支持二级回复，评论本身也有「待审核 / 已通过 / 已隐藏」状态，管理员可以隐藏不当评论；
收藏是同一个接口来回切，一个人对同一篇新闻只会有一条收藏记录。
- **后台管理**：数据统计（用户数、新闻数、待审核数、总浏览量、各分类的新闻量）、用户管理（改角色 / 禁用 /
逻辑删除）、分类管理、新闻审核、评论管理、操作日志 —— 这类操作每做一次就写一条日志，记了操作人、
操作对象和 IP。
- **另外三块**：视频点播带弹幕（滚动 / 顶部 / 底部三种位置，可自选颜色和出现的时间点）；论坛能发帖、回复、
置顶、关闭，帖子被回复时给作者发一条站内消息；话题投票支持单选 / 多选和截止时间，一个人只能投一次。
- **数据与规模**：一共 14 张表（用户、分类、新闻、评论、收藏、操作日志、视频、弹幕、帖子、回复、投票、
选项、投票记录、站内消息），开发时用的是 SQLite3，配置里留了切 MySQL 的注释；
后端 19 个 `.py` 文件共 1845 行，前端 31 个页面组件。代码里最早的文件是 2026 年 3 月，论文定稿在 2026 年 5 月。
这套东西是在本机跑的（启动脚本里就是 `127.0.0.1:8000` 和 `localhost:5173`），代码里没有部署配置，**没有上线**。
