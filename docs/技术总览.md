## 1. 架构与数据流

### 1.1 一条改动从下手到上线

```
写内容：网页后台(Pages CMS) ──保存──▶ 往 GitHub 提交一次 commit ┐
写代码：本地改 → git push ────────────────────────────────────┤
                                                              ▼
                              GitHub Actions（.github/workflows/deploy.yml）
                                ├─ actions/checkout@v4（含 submodule）
                                ├─ peaceiris/actions-hugo@v3（0.167.0 extended）
                                ├─ hugo --minify --gc   →  ./public
                                └─ cloudflare/wrangler-action@v3（wranglerVersion: '4'）
                                                              ▼
                                          Cloudflare Workers（一个 Worker，两件事）
                                            ├─ 静态资源 ./public  ← 所有请求原样返回（§2.2）
                                            └─ worker/index.mjs   ← 页面访问打点（§2.4，唯一会抛错的东西）
                                                              ▼
                                                   https://yunblog.com.cn
```

**关键点**：`main` 分支就是生产环境。没有预览环境、没有灰度，
所以**任何推到 `main` 的东西都会在 1 分钟后上线**。

### 1.3 零第三方 JS 原则

> ## ⚠️ 先说例外：页面上确实有一个外链脚本
>
> **「仓库里没有 CDN 脚本」≠「页面上没有外链脚本」。**
> 2026-10-10 实测线上 7 个页面（首页 / 关于 / 技能 / 正文 / 音乐 / 标签 / 归档），
> **每页都有且仅有 1 个外链脚本**：
>
> ```html
> <script type="module"
>   src="https://static.cloudflareinsights.com/beacon.min.js/v4bc70e2c01a94c73b74392e4234840661791215815920"
>   integrity="sha512-L0ha0OXavK/8okipN9F8BtP84dg9DUhPERbBXzwI6dgTA55d2+yweo3pn5CSFYs45/r8md2+xvUPtTdvTNRfjA=="
>   data-cf-beacon='{"version":"2024.11.0","token":"b4f9404d70084defb3b0ba78f48ce4c1","r":1,"spa":2}'
>   crossorigin="anonymous"></script>
> ```
>
> 这是 **Cloudflare Web Analytics** 的统计 beacon，**由 Cloudflare 在代理层自动注入**。
> **仓库里根本没有它** —— `public/` 下 0 处命中、`layouts/` 里也没有；
> 所以任何人「只读仓库」都不可能发现它（这就是当初把「零第三方」写成绝对说法、写错的原因）。
>
> | 关于这个例外 | |
> | --- | --- |
> | 谁注入的 | Cloudflare 的 **Web Analytics「自动设置」**。域名走 Cloudflare 代理时它**默认就开着**（`wrangler.toml`、`layouts/` 里都没有它的开关） |
> | 注入条件 | 响应是 HTML，**且请求的 `Accept` 头里含 `text/html`**。⚠️ `curl` 默认发 `Accept: */*`，**因此抓不到它** —— 裸 `curl` 会给你一个「没有外链脚本」的假结论 |
> | 覆盖范围 | 该域名下所有 HTML 页面（含子域） |
> | 数据发去哪 | 自动注入模式下发回**本站自己的** `/cdn-cgi/rum`；只有脚本本体来自 `static.cloudflareinsights.com` |
> | 怎么关 | Cloudflare 后台 → **Web Analytics** → 该站 → **Manage site** → 把自动设置改成 **Disable**（还有一档「Enable with JS Snippet installation」＝不再自动注入）<br>直达：<https://dash.cloudflare.com/?to=/:account/web-analytics> |
> | 另一个关法 | 让响应带 `Cache-Control: public, no-transform`，Cloudflare 就不能改写 HTML（会连注入一起停掉） |
>
> **站主明确要求保留它**（它在 Cloudflare 后台的 Web Analytics 里出数，与本项目自己的
> 服务端统计 [§2.4](#24-服务端逻辑页面访问打点本站唯一的服务端模块) 是两套东西，互不影响：
> `/cdn-cgi/rum` 是 **POST**、不是页面导航，所以不会被本站的页面访问统计计入）。
>
> ✅ **一个已经查过的疑点：统计 Worker 会不会挡住 beacon 上报？——不会。**
> `run_worker_first = true` 之后所有请求都先过 Worker，而 `/cdn-cgi/rum` 正是 beacon 的上报端点，
> 一度担心 `env.ASSETS.fetch()` 找不到这个"资源"会回 404、把平台统计弄哑。
> 2026-10-10 部署完**实测**（都带上 `Origin` / `Referer`，见下面的坑）：
>
> | 探针 | 结果 | 说明 |
> | --- | --- | --- |
> | `GET /cdn-cgi/rum` | **405** + `Allow: POST, OPTIONS`，返回体是 Cloudflare 自己那段说明 | 端点活着，**由 Cloudflare 在边缘处理** |
> | `POST /cdn-cgi/rum`（伪造负载） | 404，但返回体是 **Cloudflare 自己的** `<center>cloudflare</center>` 页 | 不是本站那张 Hugo 404 页 → **请求没进我们的 Worker** |
> | `GET /cdn-cgi/trace` / `/cdn-cgi/speculation` | 200 | 同为边缘端点 |
>
> 结论：**`/cdn-cgi/*` 这一类边缘路径不必在 `run_worker_first` 里排除**，beacon 上报链路是通的。
> ⚠️ 但探这个端点必须带 `Origin` / `Referer`：不带的话连 Cloudflare 都回 404（端点本身要校验来源），
> 很容易误判成「被 Worker 挡住了」——**这就是一次差点写错的结论**。

**本站自己的代码，零第三方依赖**：仓库里没有 `package.json`，`assets/js/*.js` 与
`assets/css/extended/fluent.css` 一个库都没引，所有交互都是手写的原生 JS/CSS，
由 Hugo 资源管线（`resources.Minify` + `resources.Fingerprint` + SRI `integrity`）打包。

> 💡 **写这句话的正确姿势**：主语一定要落在「**本站的代码 / 仓库里**」。
> 一旦写成「页面上没有任何…」「全站不含任何…」，就变成了关于**线上产物**的断言 ——
> 而线上产物不只有你的仓库，还有代理层、平台层加的东西。详见 [§5.3 坑 23](#53-已踩过的坑)。

为什么坚持零依赖：

- 站点是**纯静态 + 免费额度**，引一个库就要考虑版本、CDN 可达性（国内访问）、供应链风险；
- 每个模块只有几百行，自己写反而更好控制（比如「切页时音乐不能断」这种需求，现成库都不管）；
- 换来的代价写在 [§4 各模块](#4-功能模块) 里 —— 手写意味着**那些看起来多余的守卫注释必须保留**。

> ⚠️ 唯一「外部代码」是主题的 `fastsearch.js`（搜索页）和主题自己的 `head.html`/`footer.html`。
> 这些我们一律**不改**，需要换皮就在 `layouts/` 里覆盖同名文件、在 CSS 里覆盖选择器。

### 1.4 页面的 z-index 阶梯

这个阶梯是**故意排好的**，改动任何一层之前先看一眼：

| 层 | z-index | 谁 | 说明 |
| --- | --- | --- | --- |
| 背景图（轮换层） | **-2** | `#fc-bg` | 在可读性遮罩**之下** |
| 可读性遮罩 | **-1** | `body::after` | 由 `--fc-clarity` 驱动 |
| 底衬 | **-1** | `.fc-section-title::before` 等 | 局部（`isolation: isolate` 内） |
| 正文内容 | 0 | | |
| 粘性页头 | **50** | `.header` | |
| 樱花 canvas | **55** | `#fc-sakura` | 高于页头与内容，**低于**播放控件 |
| 迷你播放条 | **60** | `#fc-mini` | 花瓣不许盖住播放按钮 |
| 樱花开关 / 清晰度滑块 | **61** | | |
| 复制提示 toast | **70** | `.fc-copy-toast` | 最上层 |

首屏背景是 `body::before`（`z-index: -2`），它**不参与轮换** —— 只是「JS 还没接管」时的底。

## 2. 部署链路

### 2.1 GitHub Actions 干什么

`.github/workflows/deploy.yml`，触发条件是 **push 到 `main`** 或手动 `workflow_dispatch`。

| 步骤 | 为什么这么做 |
| --- | --- |
| `actions/checkout@v4` + `submodules: recursive` | 主题是 **git submodule**（不是 npm 依赖）。不递归拉就是空目录，**必然构建失败** |
| `fetch-depth: 0` | PaperMod 用 git 历史算 `.Lastmod` / `.GitInfo` |
| `peaceiris/actions-hugo@v3`（`0.167.0` + `extended: true`） | 版本必须与本地一致；**必须 extended**（主题的 SCSS / 图片处理要用） |
| `hugo --minify --gc` | 产物进 `./public`，正好是 `wrangler.toml` 里指定的目录 |
| 先用 `curl` 验证 `CLOUDFLARE_API_TOKEN` | 把「令牌无效」和「wrangler 报错」分开，一眼能分清是哪一类问题。**只打印 HTTP 状态码与响应体，绝不打印令牌本身** |
| `cloudflare/wrangler-action@v3` + **`wranglerVersion: '4'`** | ⚠️ 见下方。这一步同时上传**静态资源 `./public`** 和 **`worker/index.mjs`**（§2.4） |

⚠️ **`wranglerVersion` 必须锁 `4`**：`wrangler-action@v3` 默认装的是 wrangler **3.90.0**（2024 年的版本），
它不认识 `wrangler.toml` 里 `compatibility_date = "2026-10-09"` 这种未来日期，对 `[assets]` 的支持也不全，
表现是 `The process '/usr/local/bin/npx' failed with exit code 1`。本地部署用的是 wrangler 4.x，钉到 4 保持一致。

`CLOUDFLARE_ACCOUNT_ID` 不是敏感信息，直接写在 workflow 里；`CLOUDFLARE_API_TOKEN` 走仓库 Secrets
（至少需要 `Workers Scripts: Edit`；若报 not authorized，再去补 `Account → Account Settings → Read`）。

### 2.2 Cloudflare Workers 与 wrangler.toml

```toml
name = "my-blog"
compatibility_date = "2026-10-09"

main = "./worker/index.mjs"        # 服务端逻辑入口（§2.4）；加它之前这里是「无脚本」的

[assets]
directory = "./public"
binding = "ASSETS"                 # 给 Worker 一个资源绑定：env.ASSETS.fetch(request)
run_worker_first = true            # ⚠️ 必须 true，理由见 §2.4

[[analytics_engine_datasets]]      # 访问统计的落库位置
binding = "VISITS"
dataset = "my_blog_pageviews"
```

**`[assets] directory = "./public"` 不可动** —— 它是 Hugo 产物目录与部署目标的唯一连接点。
改 Hugo 的输出目录（比如 `-d dist`）而不改这里，线上就会发布一个空站点。

**`run_worker_first = true` 也不可动**（想关统计请按 [`docs/访问统计.md`](访问统计.md) §9.2 的顺序删）：

- Cloudflare 的默认行为是「**静态资源优先**」：URL 命中某个文件时，请求**根本不会调用 Worker 脚本**。
  而本站几乎每个 URL 都命中文件 —— 于是打点**一次都不会触发，还不报错**（坑 17）。
- 代价：图片 / CSS / JS / 音乐也要先过一次 Worker，再原样返回。
  实测本地 dev 下页面 3~15ms、图片 5ms，与是否经过 Worker 没有可见差别。
  真想省掉这一次调用，可以把 `run_worker_first` 改成**路径白名单数组**
  （`["/*", "!/images/*", "!/css/*", …]`，Cloudflare 支持这种写法，被排除的路径直接由资源服务器处理）。
  现在没这么做，是为了让「所有请求都走同一条路径」这件事**好读、好回滚**。

### 2.3 本地构建

```powershell
# ⚠️ 缓存目录必须是「绝对路径」。Hugo 0.167 起用相对路径会直接失败：
#    ERROR failed to create config from result: failed to decode "caches":
#    ".hugo_cache\my-blog" must resolve to an absolute directory
$env:HUGO_CACHEDIR = "D:\dsh\个人博客\my-blog\.hugo_cache"

```

> 想在本机完整走一遍 pjax / 无刷新切页，光构建还不够：菜单链接是 `absLangURL` 生成的**绝对地址**，
> 指向 `https://yunblog.com.cn/...`。本地起静态服务时它们跨域，pjax 会（正确地）拒绝接管。
> 要本地验证 pjax，得用本地 baseURL 另外构建一份看看：

### 2.4 服务端逻辑：页面访问打点（本站唯一的服务端模块）

**文件**：`worker/index.mjs`（唯一逻辑）· `wrangler.toml`（入口与绑定）·
`tools/test-pageview.mjs`（自测）· `tools/query-visits.mjs`（查数据）
**面向站主的说明**：[`docs/访问统计.md`](访问统计.md)（口径、怎么看、怎么关、怎么回滚）

> ⚠️ **前置条件（账号级、只做一次）**：Analytics Engine 必须在 Cloudflare 后台**手动启用**，
> 否则 `wrangler deploy` 会直接失败并报 `You need to enable Analytics Engine. [code: 10089]`。
> 失败**不会**让站点变坏（线上停在最后一个成功部署的版本），但会让 **CI 一直红、
> 连站主在后台写的文章都发不出去** —— 所以这是个必须尽快处理掉的卡点，不是可以放着的警告。
> 启用入口与善后步骤见 [`访问统计.md`](访问统计.md) §0（坑 21）。

#### 它改变了什么（这是本站第一次有服务端代码）

| | 加之前 | 加之后 |
| --- | --- | --- |
| Worker 在干什么 | 只发静态资源 | 先跑一段脚本，再由脚本去取静态资源 |
| 出错的可能性 | 几乎没有（没有脚本） | **脚本里的任何异常都可能影响所有响应** |
| 请求路径 | 资源服务器直接回 | 每个请求都过一次 Worker，`env.ASSETS.fetch(request)` 再回 |
| 访客数据 | 只有「请求数」（≠访客数） | 页面 / 访客 / 国家 / 来源 / 设备，见 §2.4 口径 |

**这个模块存在的唯一风险就是「它把站点搞挂」**，所以整个设计围绕一条铁律：

```
     页面响应与打点彻底解耦 —— 打点出任何事，页面都必须照常返回
```

> ⚠️ **`fetch()` 里的三行顺序不能调**（`worker/index.mjs` 里也有同样的注释）：
> ```js
> const response = await env.ASSETS.fetch(request);   // ① 先拿响应（与加统计前同一条路径）
> try { if (shouldCount(...)) ctx.waitUntil(record(...).catch(() => {})); } catch (_) {}
> return response;                                     // ② 原样返回那个响应对象本身
> ```
> 反过来写（先打点再取资源）就等于把统计放到了页面响应的关键路径上：
> Analytics Engine 抖一下、代码写错一行，访客看到的就是白屏而不是文章。
> **判定的依据是响应状态码**（只认 200/304），所以「先拿响应」不只是为了安全，也是口径本身的要求。

#### 口径（完整版见 [`访问统计.md`](访问统计.md) §3）

| 算一次访问 | 不算 |
| --- | --- |
| 整页导航（`Sec-Fetch-Dest: document`） | 图片 / CSS / JS / 字体 / 音乐（`Sec-Fetch-Dest` 不是 document） |
| **pjax 站内切页**（认 `X-PJAX: 1`，见下） | 悬停预取（`X-PJAX-Prefetch`）与浏览器预取（`Sec-Purpose: prefetch`） |
| `304`（协商缓存，页面确实渲染了） | 3xx 跳转（同一页会被记两遍）、404/5xx |
| 老浏览器按 `Accept: text/html` 兜底 | 明显爬虫的 UA（`BOT_UA_MARKERS`）、空 UA、`HEAD` |

**pjax 那一条是本站特有的坑**：站内跳转走的是前端 `fetch()`，浏览器给它报的
`Sec-Fetch-Dest` 是 `empty` 而不是 `document` —— 只认 document 的话，
「进首页算 1 次、点开五篇文章算 0 次」。好在 `assets/js/pjax.js` **本来就带 `X-PJAX: 1`**
（它自己用这个头做别的事），所以服务端直接认它就行，**pjax 代码一个字都没改**。

**同理，Speculation Rules 的预取必须挡掉**：`extend_head.html` 里那段 prefetch 会在鼠标扫过链接时
发出**完整的 HTML 请求**，不挡的话「扫一遍鼠标」就能刷出十几次访问（§4.1 提到的那个 prefetch 规则）。

#### 关键取值

| 取值 | 值 | 为什么 |
| --- | --- | --- |
| 访客去重 | `SHA-256(IP + UA + 当天盐)[:32]` 存 `index1` | **不存原始 IP**；盐每天换 → 当天能去重、跨天对不上（断掉长期跟踪） |
| 「一天」的边界 | **UTC**（= 北京时间早 8 点） | 与 Analytics Engine 的 `timestamp`（也是 UTC）严格对齐，否则跨日那几小时会重复计 |
| `indexes` | **只放一个值** | ⚠️ Analytics Engine 给两个 index 会**不报错、直接丢弃整条**（坑 18） |
| 来源 | 只留**主机名**，站内记 `internal`，没有记 `direct` | 完整网址会带上别人的搜索词与内部路径 |
| 路径 | 去掉末尾斜杠、去掉查询串、截断 200 字符 | `/posts/foo`、`/posts/foo/`、`/posts/foo/index.html` 必须并成一行 |
| 保留期 | **3 个月**（Analytics Engine 固定上限） | 想要更长历史得自己导出 |
| 额度 | 免费每天 10 万数据点 / 1 万次查询 | 一次访问 = 一个数据点，本站差两三个数量级 |

#### 本地能验到哪一步（⚠️ 有一条验不了）

## 3. 内容管理 Pages CMS

### 3.1 .pages.yml 管什么

[Pages CMS](https://pagescms.org) 是「Git 型 CMS」：它不存内容，只是在你的仓库上做增删改并提交 commit。
`.pages.yml` 决定**后台左侧出现哪些栏目、每个栏目里能改哪些字段**。

```yaml
media:                    # 图床：上传落到 static/images/，公开路径是 /images/xxx.jpg
  - name: images
    input: static/images
    output: /images
    rename: safe

content:                  # 后台能编辑的东西
  - name: posts   type: collection   path: content/posts        # 文章（可增删）
  - name: about   type: file         path: content/about/index.md  # 关于/公告（单文件）
  - name: resume  type: file         path: content/resume/index.md # 个人简历（单文件）
  - name: skills  type: file         path: data/skills.yaml  list: true  # 技能（整个文件是一个数组）
```

### 3.2 现有四个集合

| 后台里叫什么 | 类型 | 对应文件 | 说明 |
| --- | --- | --- | --- |
| **文章** | `collection` | `content/posts/*.md` | 日常写作；列表页里也会列出 `content/posts/_index.md`（**那是栏目设置，别删**） |
| **关于 / 公告** | `file` | `content/about/index.md` | 公告页；它的 `summary` 和 `cover.image` **同时**喂给首页作者卡的小标签（见 §4.11） |
| **个人简历** | `file` | `content/resume/index.md` | 简历页 `/resume/`；它的 `label` **同时**喂给首页作者卡头像下面那条小条（见 §4.16） |
| **技能 / 技术栈** | `file` + `list: true` | `data/skills.yaml` | 整份清单就是一个顶层数组，分类与技术都可增删 |

### 3.3 踩坑记录

这几条都是**真踩过的**，改 `.pages.yml` 前必读。

#### ① 字段类型里**没有** `list` 这种 type

要「可重复」是给字段加 **`list: true` 这个属性**，不是写 `type: list`：

```yaml
- name: tags
  type: string
  list: true        # ✅ 对
# type: list       # ❌ 后台里这个字段直接不生效
```

对象也能重复，`list: true` 或 `list: { min, max, collapsible }` 都行。

#### ② 正文的字段名**必须**叫 `body`

`body` 是保留名，代表 front matter **下面**那段正文；叫别的名字（如 `content`）会被当成普通 front matter 字段。
正文类型用 `type: rich-text`。

#### ③ 单文件页面用 `type: file`

一个页面就是一个文件时（关于页、技能清单），用 `type: file` + `path` 指向那**一个文件**，
不要用只有一个文件的 `collection`。`format: yaml-frontmatter` 对应 Hugo 的 `---` 分隔。

#### ④ ⚠️ 最重要：**没在 `fields` 里声明的 front matter 键，保存时会被丢掉**

Pages CMS 保存时会按 `fields` 重新拼一遍 front matter。它的源码里（`lib/schema.ts` 的 `deepMap`）
**只遍历 `fields` 里列出的字段**，对象之外一层的其他键**不会被写回**。

后果：如果某个页面的**网址或模板依赖 front matter**（比如 `url:` / `layout:`），
而后台没声明这两个字段，那么站主**第一次在后台点保存，这个页面就散了**。

本站的对策 —— **让页面不依赖 front matter 里的 url / layout**：

```
content/about/index.md   ← 叶子包
  · 网址 /about/ 由「目录名」决定
  · 所用模板由「目录名决定的 type = about」选中（layouts/about/single.html）
  · front matter 里只有 title / subtitle / summary / cover —— 全是后台声明过的，丢不掉
```

> 以后新增「后台要能改」的页面时，照这个套路：**能靠目录名确定的，就别写进 front matter。**
> 实在必须写（比如需要一个自定义字段），就**在 `.pages.yml` 里声明它**，哪怕用 `hidden: true` 藏着。

#### ⑤ 集合级的 `media: images` 已经不被认了

文章那个集合里有一行 `media: images`，那是**早期写法**。用 Pages CMS 自己的配置校验器跑一遍会报
`content.0 :: Unrecognized key: "media"`。

现在指定图床的正确位置是**字段自己的 `options.media`**：

```yaml
- name: image
  type: image
  options:
    media: images     # ✅ 指向 media: 里那个 name
```

（文章那行属于历史遗留，改了可能影响站主习惯的图床行为，**没人明确要求就别动它**。）

### 3.4 怎么验证后台配置真的生效

**别只跑 Hugo 构建就说「配好了」** —— Hugo 根本不读 `.pages.yml`，它绿了不代表后台能用。

两条能真跑的验证：

1. **用 Pages CMS 自己的校验器跑一遍**。上游仓库 [`hunvreus/pagescms`](https://github.com/hunvreus/pagescms)
   里的 `lib/config-schema.ts` 就是后台校验 `.pages.yml` 用的那份 Zod Schema，
   `lib/serialization.ts` 是它读写 front matter 的那份代码。把这两个文件取下来、
   把 `@/fields/registry` 换成一份只导出 `fieldTypes` 的桩（那 12 个类型名从上游 `fields/registry.ts` 抄），
   再 `npm i zod yaml`，就能在本地对 `.pages.yml` 跑 `ConfigSchema.safeParse(...)`。
2. **模拟一次「后台保存」，再用真 Hugo 构建**。用上面那份 `parse`/`stringify` 走一遍
   「读文件 → 只留声明过的字段 → 写回」，把结果喂给 Hugo，确认页面**网址没变、模板没丢、正文还在**，
   并且首页派生出来的东西（如公告小标签）跟着更新了。

> 本机登不进站主的 Pages CMS（要 GitHub App 授权），所以只能做到这个程度。
> 真正的「点一次 Save」最终仍要站主自己确认一次。

## 4. 功能模块

### 4.1 自研 pjax 无刷新切页

**文件**：`assets/js/pjax.js`（唯一的核心；配套 `assets/js/nav-rail.js`、`nav-posts.js` 靠 MutationObserver 感知切页）

**做什么**：拦截站内链接 → `fetch` 目标页 → 只替换 `<main class="main">`，
再同步 `<title>`、顶部导航高亮、`body` 的类、页面专属 head 资源。

**为什么值得自己写**：音频对象是 `new Audio()` 持有的、**不在 DOM 里**，
所以换内容区时音乐**完全不会中断**。换成整页跳转就一定会断。

| 关键取值 | 值 | 为什么 |
| --- | --- | --- |
| 替换范围 | 只有 `main.main` | 页头、页脚、播放条、樱花、滑块、状态栏都在它外面，所以永远不被换掉 |
| 预取缓存 | `Map`，`CACHE_MAX = 20`，LRU | 悬停/聚焦/touchstart 时提前取，点下去就是秒开 |
| 悬停延迟 | `HOVER_DELAY = 80` | 鼠标扫过不算，真的要点了才取 |
| 超时 | `TIMEOUT = 10000` | 超时 abort，回退成整页跳转 |
| 不接管 | `/search/` | 主题的搜索脚本绑在 `window load` 上，无刷新换内容后不会重新初始化，这一页交给浏览器正常跳转最稳 |

**几个必须保留的守卫**（删了就会出 bug，别当冗余代码清理）：

- **`navSeq` 导航编号** —— 连续快点几个链接时，旧请求被 `abort` 后**不能再反过来触发整页跳转**，
  否则会「抢跳」把后点的链接顶掉。只有最新一次导航允许回退。
- **View Transition 里临时摘掉迷你条的 `view-transition-name`**（`dropMiniName`）——
  命名元素的旧快照在「退场」时会**一直留在屏幕上直到过渡结束**，看着像重复显示。
- **`syncBody` 里的 `keep = ['fc-has-mini']`** —— `body.className` 整个被换掉，
  运行时加的类要显式保留。`fc-has-player` 不在这里，因为紧接着 pjax 自己会算一遍（那是兜底，
  万一播放器脚本没跑起来，CSS 里 `body.fc-has-player` 那条规则也能保证两条播放条不同时出现）。
- **降级**：缺 `fetch`/`DOMParser`/`pushState`、fetch 失败、目标页结构不对、外链、
  `target=_blank`、`download`、`data-no-pjax`、纯 `#hash`、`mailto:` → 一律不拦，退化成普通多页站点。
  **任何情况都不能把站点搞坏。**

> ⚠️ **跨模块耦合**：`layouts/_partials/extend_head.html` 里那段 **Speculation Rules 只能用 `prefetch`，
> 绝对不能改成 `prerender`**。prerender 会在后台真正渲染目标页并**整个替换文档** ——
> 音频会立刻断，pjax 的整个前提（文档不换）也没了。

### 4.2 全站唯一的音乐播放器

**文件**：`assets/js/music-player.js`（约 700 行）、`layouts/_partials/music_player.html`、
`layouts/music.html`、`layouts/_partials/extend_footer.html`（迷你条）

**做什么**：**一个 `<audio>`（`new Audio()`，不在 DOM 里）驱动三种视图**：

| 视图 | 在哪 | 生命周期 |
| --- | --- | --- |
| 播放器大卡 `#fc-player` + 歌词条 `#fc-lyric` | 首页内容区 | pjax 换页时**被重建** |
| 迷你播放条 `#fc-mini` | 页脚（常驻区） | **永不被替换** |
| `/music/` 页的大卡 + 整页歌词 | `layouts/music.html` | 换页时被重建 |

**关键设计**：

- **`/music/` 页没有第二个播放器**：它直接复用首页那张大卡的同一个 partial
  （`_partials/music_player.html`），所以 id 与 `data-fc` 钩子完全一致，同一个 `<audio>` 换页后照旧驱动它。
- **两条播放条不会同时出现**：`toggleMiniVisibility()` 按「页面上有没有 `#fc-player`」决定，
  结果写到 `body` 上的 `fc-has-player` / `fc-has-mini` 两个类，由 CSS 负责显隐。
  pjax 换完内容后也会调 `window.fcMusic.refresh()` 重新查询 DOM、重绑控件、把当前状态刷到新界面上。
- **没有 pjax 时的降级**：`localStorage` 记 `{曲目, 进度, 播放状态}`（`fc-music-state`，播放中最多每秒写一次），
  新页面读回来 `seek` 到同一位置再尝试续播；被浏览器自动播放策略拒绝时**老实停在暂停态**（位置已就位）。
- 音量单独存（`fc-music-volume`），全局不随曲目变化。
- 歌词是自写的 LRC 解析（零依赖），制作信息角色名单 `CREDIT_ROLES` 与 `tools/prepare-music.py` 保持一致。

### 4.3 背景图轮换

**文件**：`assets/js/background.js`、`assets/css/extended/fluent.css` 第 14 节、`_partials/extend_footer.html`（注入图片列表）

**做什么**：全屏背景每 **30 秒**换一张，两层交叉淡入（900ms），起始索引每次访问随机。

| 关键取值 | 值 | 为什么 |
| --- | --- | --- |
| 间隔 | `INTERVAL = 30000` | |
| 层数 | 2（`#fc-bg-a` / `#fc-bg-b`，`z-index: -2`） | 把下一张放进**隐藏那层**再淡入 = 真正的交叉淡入，不闪 |
| 起始图 | 随机 | 每次进来不一样 |
| 轮换池 | `assets/images/background.jpg` + `assets/images/bg/*`（当前共 **8 张**） | URL 由 Hugo 注入 `#fc-bg-data` 的 JSON，**加图只要丢进目录**，不用改 JS |
| 不可见时 | `visibilitychange` → 停掉定时器 | 别在后台标签页里白换图 |

**为什么不会闪**：切换前先 `new Image()` 确认目标图 `onload`（失败也静默往下走），
并且新层写进 `backgroundImage` 后先 `void offsetWidth` 强制一次布局，再触发 `opacity` 过渡。

**首屏为什么不空白**：`body::before` 仍然是那张 `background.jpg`（`z-index: -2`），
它**不参与轮换** —— JS 没跑到、跑得慢、图片还没下载完，看到的都和以前一样。

> ⚠️ 轮换层的 `z-index` **必须是 -2**：可读性遮罩 `body::after` 是 -1，遮罩得盖在轮换后的图上面。
> 写成 -1 或者 0，遮罩就失效了。

### 4.4 左下角背景清晰度滑块

**文件**：`assets/js/bg-clarity.js`、`fluent.css` 第 19 节、`_partials/extend_footer.html`（渲染）、
`_partials/extend_head.html`（注入默认档）、`hugo.toml` 的 `params.bgClarityDefault`

**做什么**：让访客自己决定背景图透出多少。**刻度 0 ~ 100**。

> **核心公式：遮罩不透明度 = 100 − 清晰度**
> `0` = 背景全遮住 · `40` = 遮 60%（**默认档**） · `100` = **遮罩为 0**，背景原图直接铺满。
>
> ⚠️ **方向最容易记反**：清晰度**越大**，遮罩**越薄**。改任何跟它相关的计算前先念一遍这句。

| 关键设计 | 为什么这么写 |
| --- | --- |
| 拖动**只改一个** CSS 变量 `--fc-clarity` | 渐变本身写在 CSS 里，用 `calc((100 - var(--fc-clarity)) / 100 …)` 算出来。所以拖动时**不重拼渐变字符串**、不碰别的样式，每次 `input` 只写一个变量 |
| 默认值来自 `hugo.toml` 的 `params.bgClarityDefault` | **脚本里没有硬编码数字**。`extend_head.html` 注入 `:root{--fc-clarity:N}`（保证首屏就是正确档位，不会先按兜底值画一次再跳），`extend_footer.html` 把它写进 `<input value>`。**`<input>` 的 value 是唯一真相**，脚本首屏再对齐一次 |
| 拖动 / 触摸 / 键盘全交给原生 `<input type="range">` | 用 `input` 事件（拖动中连续触发），**不用 `change`**（只在松手时触发一次）。方向键 / Home / End 自带，手机上手势也是浏览器保证的，不需要自己写 pointer 事件 |
| **刻意不写 `localStorage`** | 站主要的是「所有访客进来都是默认值 40」。**不要"顺手"加上记忆** |
| 渲染在 `main.main` **之外** | pjax 只替换内容区，所以它不会被换掉、不会重复挂载、访客拉过的数值也不会被重置。脚本里再加一道 `data-fc-ready` 幂等守卫双保险 |
| 显式同步 `aria-valuenow` | 元素声明了 `role="slider"`，读屏要读它，不跟着改会报旧值 |

**遮罩之外它还牵动两样东西**（这是**反直觉**的地方，见下一节）：底衬的厚度也由 `--fc-clarity` 算出来。

### 4.5 压在背景上的文字必须有底衬

**文件**：`fluent.css` 第 1 节（`--fc-bare-backing` / `--fc-footer-backing`）、第 2 节（用法）

**背景**：访客能把遮罩拉到 **0**（背景无遮挡）。

**问题**：直接压在背景图上的文字（区域标题、页头、页脚）此时底下一无所有。
而且**单靠遮罩不可能**让这类文字达到 3:1 对比度 —— 底图从纯黑到纯白，
文字无论什么颜色理论上限只有 2.86:1（浅色）/ 3.19:1（深色）。

**做法**：给这些元素加一层**局部**底衬 —— `::before` 铺一层纯色，再用 `filter: blur(8px)` 让它四周化开。
中间仍是实心的一层（所以文字正后方的对比度可测、稳定），边缘却没有硬边，**不描边、不加阴影，不会变成一张卡片**。

```
--fc-bare-backing:   rgba(255,255,255, calc(0.60 * var(--fc-clarity) / 100))   /* 浅色 */
--fc-footer-backing: rgba(255,255,255, calc(0.80 * var(--fc-clarity) / 100))   /* 页脚 12px 灰字，最吃底 */
深色：rgba(10,12,16, 0.70 / 0.80 * …)
```

⚠️ **底衬厚度跟着清晰度走，而且是「清晰度越高底衬越厚」** —— 因为清晰度越高遮罩越薄、越需要底衬兜底。
拉到 0 时底衬正好也是 0（不会在已经发白的背景上再糊一道白）。**这个方向和直觉相反，别改。**

**横向外扩有上限**：`.fc-section-title::before` / `.page-header::before` 只外扩 `-10px -12px` ——
这两个元素在窄屏上离视口左右各只有 14px，外扩太多会顶出横向滚动条（实测过 390 / 768 / 1280 三档）。
`.footer::before` 横向**不外扩**（`.footer` 是通栏的，外扩多少就顶出多少横向溢出）。

**新增元素时**：如果它是**直接压在背景上、底下没有卡片托着**的文字，就得给它加底衬（或者干脆放进玻璃卡里）。
卡片里的内容有卡片底色托着，一般不用管。

### 4.6 顶部导航与窄屏滑轨

**文件**：`_partials/header.html`、`assets/js/nav-rail.js`、`fluent.css` 第 3 节 / 第 9 节、`hugo.toml`

**数据源**：`hugo.toml` 的 `[[menu.main]]`，顺序由 `weight` 决定。**当前 8 项**：
首页 · 文章 · 归档 · 标签 · 技能 · 音乐 · 关于 · 搜索。

> ⚠️ **这一份菜单是「顶部导航」和「左栏目录」共用的单一数据源**（见 §4.7）。
> 加一项只改 `hugo.toml`，两边都会出现；左栏的图标在 `_partials/nav_icon.html` 里按
> `identifier` 登记（没登记会落到兜底的「链环」图标）。

**窄屏滑轨**：放不下时不换行，改成**横向滑轨**（不换行、当前项自动定位、两端渐隐）。
它没有「到某个宽度才切成滑轨」的断点 —— 内容放得下时 `scrollWidth` 恒等于 `clientWidth`，
既滑不动也不会有渐隐，**这就是渐进增强**。

| 关键取值 | 值 | 为什么 |
| --- | --- | --- |
| 两端渐隐薄片 | 32px 宽，内缩 3px（= 容器 padding） | 不提示的话访客根本不知道右边还有东西。底色与模糊跟容器一致，深浅色、任意背景都合得上 |
| 渐隐挂在 `.fc-nav-rail`（外层）而不是滚动容器上 | 绝对定位的伪元素挂在滚动容器上会**跟着内容一起滚走**，滑两下提示就没影了 |
| 当前项余量 `PAD = 10` | 浏览器自带的会把目标贴到容器最边上，正好落在渐隐里，看着像没选中 |
| 鼠标横拖阈值 `GRAB = 6` | 横move 不到 6px 一律当点击；一旦真拖了就把紧随其后的 `click` 吃掉 |
| 转屏/改窗口 | `resize` 节流 **120ms** 后重算 |

**切页后怎么自动定位**：`nav-rail.js` 用 **MutationObserver 盯 `#menu` 上的 `active` / `aria-current`** ——
pjax 只换 `main.main`（导航不被替换），但会把这些 class 照抄到 `#menu` 上，
所以不用改 pjax 核心就能拿到「切页完成」的通知。

⚠️ **断点是两档，别合并**：

| 断点 | 管什么 |
| --- | --- |
| **880px** | **只管页头与导航**（折行 + 滑轨 + 44px 触摸目标 + 隐藏站名文字） |
| **768px** | 卡片单列、头像缩小、正文内边距 |

为什么导航单独用 880px：8 项那条分段控件**自己就要约 764px**（每项 ≈95px = 2 个汉字 14.5px + 左右各 16px），
再加页头左右各 24px 内边距 —— **视口窄于约 812px 时它连独占一整行都放不下**，
会被 `body` 的 `overflow-x: clip` 悄悄裁掉最后一项（实测 800px 时「搜索」被切掉 14px，
而且**没有任何渐隐提示**，看着像点不到）。所以 880px 及以下直接走手机那套「站名一行 + 导航整行滑轨」。

### 4.8 樱花飘落

**文件**：`assets/js/sakura.js`、`fluent.css` 第 13 节

- **只有非 `prefers-reduced-motion: reduce` 时才创建 canvas 与开关按钮**；
  开启减少动效时脚本直接返回，**连 canvas 都不会被创建**（CSS 里的 `display: none` 只是兜底）。
- canvas 与开关都挂在 `<body>` 上（`main.main` 之外），pjax 切页时不重建、不闪，rAF 也不被打断。
- **canvas 刻意不加 `view-transition-name`**，不参与切页过渡（否则会有独立动效）。
- `z-index: 55` —— 高于页头(50)与卡片内容，**低于**迷你播放条(60)，花瓣不会盖住播放控件。
- 性能：花瓣数按视口宽自适应（手机 14 / 平板 24 / 桌面 34–40）；`devicePixelRatio` **封顶 2**；
  花瓣是**预渲染好的精灵图**（3 种形状 × 4 种颜色），每帧只 `drawImage`；
  切到后台停 rAF；`resize` 节流 180ms。
- 开关状态存 `localStorage`（`fc-sakura`，默认开）；关闭 = **停 rAF + 清空画布**（不是单纯隐藏）。
- 配色从 CSS 变量 `--fc-sakura-1..4` 读，**JS 里不硬编码色值**。

### 4.9 页脚状态栏

**文件**：`assets/js/statusbar.js`、`_partials/extend_footer.html`、`fluent.css` 第 17 节

- **只有一个 `setInterval(1000)`**，同时驱动时钟与运行时长（不额外开定时器）。
- 时钟**固定北京时间**（`Intl.DateTimeFormat` + `timeZone: 'Asia/Shanghai'`），**不跟随访客本地时区**。
  极端降级（`Intl` 不可用）时手动按 UTC+8 换算。
- 起始日期来自 `hugo.toml` 的 `params.siteLaunchDate`（读 `data-since` 属性），**脚本里没有硬编码日期**。
- `visibilitychange` → 后台清定时器，回前台**立即刷新一次**再重新计时。
- **幂等**：`start()` 一律先 `clear` 旧的再建新的；脚本被重复执行时走
  `window.fcStatusbar.start()` 分支，**不会出现第二个定时器**。
- pjax 只替换 `main.main`，页脚属于常驻区域，所以切页时脚本不会被重跑，时钟不重置、不闪。
- Hugo 侧会先算一份**静态文案**渲染进去，JS 没跑到 / 被禁用时也不是空白。

### 4.13 主题切换的圆形扩散

**文件**：`assets/js/theme-transition.js`、`fluent.css` 第 10 节

- 主题本身的切换逻辑**一个字都没改**（仍是主题 `footer.html` 里那个监听 `#theme-toggle` 的监听器）。
- 这里用**捕获阶段拦截 + 在过渡回调里重新派发一次点击**把它整个包起来：
  捕获阶段一定早于按钮自身的监听器 → `stopPropagation()` 让原监听器这次不执行 →
  `startViewTransition(回调)` 里再 `btn.click()` 一次，原监听器在「新快照」里正常完成切换。
  `replaying` 标志避免这次重新派发的点击又被自己拦一次。
- 圆心：鼠标点击坐标；键盘触发（`clientX/Y` 为 0）时退回按钮中心。半径 = 圆心到视口四角里**最远**那个角的距离。
- 写进 `--fc-vt-x/y/r`，由 CSS 的 `::view-transition-new(root)` 的 `clip-path` 用。
- **降级**：不支持 View Transitions 的浏览器（如 Firefox）直接放行，不报错、不卡住；`prefers-reduced-motion` 同样放行不做动画。
- ⚠️ `root` 那一对 `::view-transition-*` 是留给它的，**pjax 用的是内容区的独立命名**（`fc-page` / `fc-player`），
  两者不许抢。扩散前主题脚本会临时摘掉 pjax 那两个名字（`window.fcViewNames.clear()`），
  否则命名元素画在 root 之上、圆形盖不住它们。

### 4.14 联系方式一键复制

**文件**：`assets/js/copy-contact.js`、`fluent.css` 第 15 节

- **事件委托挂在 `document` 上**：pjax 换页后新插进来的 `[data-copy]` 按钮照样能用，
  **不需要在换页后重新绑定，也不会重复绑定**。
- 复制的值与提示语来自按钮自己的属性：`data-copy` / `data-copy-done` —— 模板里改文案即可，不用碰 JS。
- 剪贴板：优先 `navigator.clipboard.writeText`（HTTPS 才有）；不可用或被拒绝时退回
  `document.execCommand('copy')` + 临时 `textarea`；两条路都失败就提示「复制失败」，**绝不静默失败**。
- 提示条是常驻在 `<body>` 上的一个玻璃小条（`role="status"`，`aria-live="polite"`，`z-index: 70`），
  连续点击**只重置计时**，不会叠一堆；1.6 秒后淡出。

**作者卡头像下的小条**（只有一个，点进 `/resume/`）：

| | |
| --- | --- |
| 文案 | 简历页 front matter 的 `label`（空了退回页面标题） |

**「横向跟头像一样宽」是结构决定的，不是抄来的数字**：头像和小条装在 `.fc-profile-id` 这一列里，
列宽 = 头像宽，小条 `width: 100%` 撑满它。实测（2026-10-10，1280px 视口）：
头像 `76×76`、小条 `76×36`，两者左边缘同为 `x=291`、右边缘同为 `367`；
390px 视口下头像 `60×60`、小条 `60×36`，同样左右对齐。

- **高度固定 36px**：手机上这就是整块的可点区域，36px 是站内约定的触摸下限。
  最窄那一档宽度是 60px，所以「纵向比横向小」在任何断点都成立。
- ⚠️ **跨模块耦合**：`.fc-profile-id` 的宽度（76px / ≤768px 时 60px）**必须与 `.fc-avatar` 同步**。
  头像尺寸写在 fluent.css 第 5 节和 ≤768px 那一档里，**改头像尺寸时这三处要一起改**，
  否则小条就跟头像不齐了。
- **文案过长只截断、不顶宽**：`.fc-profile-badge-text` 上有 `overflow + nowrap + ellipsis`，
  并且**必须显式写 `min-width: 0`**（flex 子项默认 `min-width: auto`，不写它就不肯收缩，
  省略号永远不出现 —— 与公告小标签同一个坑）。后台把 `label` 改长了，小条仍然正好 76px 宽。
- **和公告小标签刻意不同级**：公告那个是**强调色**胶囊（`--fc-accent-soft`，卡里唯一的通栏入口，
  要显眼），这个小条是**中性**小块（`--fc-skill-bg` / `--fc-skill-stroke`，跟技能页标签同一套
  「比卡片亮一点点的静音块」令牌），字号也更小（12px / 手机 11px）。
  两者一个在头像下、一个在卡片底边，中间隔着统计和图标两排（实测相隔 **199.45px**），
  不会看成两个并排的同级按钮。

| 视口 | 卡片高度（有小条 → 没有） | 说明 |
| --- | --- | --- |

| 窄屏 | **390px 必测**：滑轨能滑、当前项可见、两端渐隐、页面不横滚 |
| 中间宽度 | 导航类改动要扫 769 / 800 / 812 / 880 / 881 / 1000 / 1071 这些**容易漏**的档 |
| 深浅色 | 两种主题都看一眼 |
| 清晰度极限 | 滑块拉到 **100**（背景无遮挡）：压在背景上的文字还读得清吗 |
| pjax | 连点 3 个页面：无整页刷新、无重复挂载、**控制台无报错**、音乐不断 |
| 后台 | 改了 `.pages.yml` 的话，用 §3.4 的办法真跑一遍校验 |

#### 判断「页面上有什么」的标准动作（坑 23–25 的通用解法）

只要你要写的是关于**线上页面**的话（「有没有第三方脚本」「有没有外部字体」「请求了几个外部域名」…），
就照这个来，**不要读仓库下结论**：

```powershell
# ⚠️ -H "Accept: text/html" 不能省：少了它 Cloudflare 不会注入 beacon，
#    你会拿到一份「干净」的 HTML，然后得出完全错误的结论（坑 24）
curl.exe -s --compressed -A "Mozilla/5.0 Chrome/141.0.0.0" -H "Accept: text/html" `
  -o live-home.html "https://yunblog.com.cn/"
```

然后数三样东西（引号可能被 Hugo 的 `--minify` 去掉，所以正则要同时吃 `src="x"` 和 `src=x`）：

- `<script src>`：站内有几个、**外链有几个，分别是谁**
- `<link rel=stylesheet href>`：**外链样式表有几个**
- 外部字体（`fonts.googleapis.com` / `fonts.gstatic.com`）、`rel=preconnect` / `dns-prefetch` 指向谁

2026-10-10 的实测结果（7 个页面一致）：**11 个 `<script src>` = 站内 10 个 + 外链 1 个（就是那个 Cloudflare beacon）**，
**外链样式表 0 个、外部字体 0 个、外链图片 0 个**；只有一个 `preconnect`/`dns-prefetch`，
指向自家的 `music.yunblog.com.cn`。
⚠️ 那 12 个 R2 音频地址只是在页面的 JSON 数据里，`<audio>` 标签数为 **0** —— **不点播放不会发起请求**。

3) 推完看一眼 GitHub Actions 有没有变绿。
4) **动过 `worker/` 或 `wrangler.toml` 的话**，另外做这三步：

node tools/test-pageview.mjs                      # 口径 + 响应原样返回，57 项必须全绿

## 6. 不要动的东西

这些东西一旦动，坏的方式往往很安静（当场看不出来，过一阵才炸）：

| 别动 | 为什么 |
| --- | --- |
| `wrangler.toml` 的 `[assets] directory = "./public"` | 部署的唯一连接点，改了会发布空站点 |
| `wrangler.toml` 的 `run_worker_first = true` | 删了（或改成 false）**不会报错**，只会让打点静默失效（坑 17）；要关统计按 [`访问统计.md`](访问统计.md) §9.2 的顺序删 |
| `worker/index.mjs` 里「**先取响应 → 再打点 → 原样返回**」的顺序 | 打点一旦进入页面响应的关键路径，统计故障就变成站点故障 |
| `worker/index.mjs` 里 `indexes` **只有一个值** | 给两个 Analytics Engine 会静默丢弃整条（坑 18） |
| `.github/workflows/deploy.yml` 的 `wranglerVersion: '4'` | 见 §5.3 坑 9 |
| `hugo.toml` 的 `baseURL` | canonical / sitemap / RSS 全靠它 |
| `body { overflow-x: clip }` | 它是很多装饰层的安全网，但也会**掩盖**溢出问题（坑 12） |
| 各常驻层挂在 `main.main` **之外** 这件事 | 这是「脚本只跑一次、状态不被重置」的根本 |
| `themes/PaperMod` | 升级主题不能冲突，要改就在项目根同名覆盖 |
| `static/music/*.mp3` | 音频在 R2；`.gitignore` 挡着，别手滑提交几百 MB |
| `data/music.yaml` | 由 `tools/prepare-music.py` 生成，**别手改** |
| `content/posts/_index.md` | 它是「文章」栏目页的设置文件，**不是一篇文章**，删了 `/posts/` 标题会空 |
| 主题自带的 `fastsearch.js` | 搜索页只换皮不改逻辑（§4.12） |
