# 访问统计 —— 这个站怎么数访客

> **给谁看**：站主本人（看数据、改口径、关掉它）+ 以后的开发 agent（改代码前先读）。
> **一句话**：访客打开页面时，**服务端**（Cloudflare Worker）记一条匿名记录，
> 存进 Cloudflare 的 Analytics Engine，你在 Cloudflare 后台就能看。
> 全程**没有第三方 JS、没有 Cookie、不存 IP** —— 这三句说的是**这一套统计自己**。
> ⚠️ 页面上另外还有**一个** Cloudflare 自动注入的统计脚本（不是本站加的、仓库里也没有），
> 见 §1.1，别把两套搞混。代码在 [`worker/index.mjs`](../worker/index.mjs)。

## ⚠️ 0. 先做这一步：去后台点一下「启用 Analytics Engine」

这是 **Analytics Engine 这个产品的账号级开关**，整个账号只用开一次，

- 因为部署失败，**线上仍然是老版本** —— 站点不会坏（这一点可以放心），
  **但是**：GitHub Actions 会一直红，**你之后在网页后台写的文章也不会被发布上线**，

**点完之后**，还要让部署真的跑一遍（启用不会自动重跑上一次失败的构建）：

- 去 GitHub 仓库的 **Actions** 页面 → 点开最近那次**失败的**构建 → 右上角 **Re-run all jobs**；
- 或者随便改点东西再提交一次（比如在后台保存一篇文章）。

跑完那一遍，"访问统计" 才真正开始工作。

## 1. 它和「Workers Metrics」有什么不一样

Cloudflare 后台那个 **Workers Metrics**（你现在在看的）统计的是**请求数**，
而这个站一个人打开首页就会产生几十个请求（8 张背景图 + CSS + JS + 封面图 + 音乐），
所以那个数字**不等于访客数**，它也不知道「谁在看、看哪些页面、从哪来、哪个国家」。

| | Workers Metrics（已有的） | 本统计（新增的） |
| --- | --- | --- |
| 数什么 | 所有请求，含图片/CSS/JS | **只数页面** |
| 访客数 | 没有这个概念 | 有（同一天同一个人算一次） |
| 看了哪些页面 | 不知道 | 知道 |
| 来源 / 国家 / 手机还是电脑 | 不知道 | 知道 |
| 数据在哪 | Cloudflare 后台 | Analytics Engine 数据集 `my_blog_pageviews` |
| 保留多久 | 按后台 | **3 个月**（Analytics Engine 的固定上限） |

两者**同时存在、互不影响**：Metrics 那个页面照旧能看到请求数、缓存命中率、4xx/5xx。

### 1.1 ⚠️ 本站其实有**两套**统计，别搞混

你在 Cloudflare 后台会看到两个不同的数据入口，它们互相独立：

| | 谁能看到 / 数据在哪 | 页面里有没有它的代码 |
| --- | --- | --- |
| **Cloudflare Web Analytics**（平台自带） | Cloudflare 后台 → **Web Analytics** | **有** —— 一个 Cloudflare **自动注入**的外链 beacon 脚本。**不是本站加的，`layouts/` 与 `public/` 里都没有它**（详见 [`技术总览.md`](技术总览.md) §1.3） |
| **本文这套服务端统计** | Analytics Engine 数据集 `my_blog_pageviews`（见 §7） | **没有** —— 浏览器端一行代码都没加，全在 Worker 里做 |

两者不冲突。beacon 的上报是 **POST 到本站域名的 `/cdn-cgi/rum`**，
而本套统计只认 `GET` + 页面导航，所以**它不会被本套统计计入**（口径见 §3）。

## 2. 它是怎么工作的

```
访客浏览器 ──► Cloudflare Worker（worker/index.mjs）
                    │
                    ├─ 1. 先取页面：env.ASSETS.fetch(request)   ← 与加统计之前完全同一条路径
                    │
                    ├─ 2. 原样返回这个响应给访客（一个字节都没改）
                    │
                    └─ 3. 顺便判断「这算不算一次访问」
                            └─ 算 → ctx.waitUntil( 写一条记录进 Analytics Engine )
```

**为什么非要「先返回、后打点」**：打点一旦挤进页面响应的关键路径，
Analytics Engine 抖一下、代码写错一行，访客看到的就是白屏而不是文章 ——
而这个站在加统计之前是「没有脚本的纯静态托管」，**根本没有出错的机会**。
所以统计这件事被设计成：**它坏了，你只会少一行数据，不会少一个访客**。
（这条铁律在 `wrangler.toml` 和 `worker/index.mjs` 里都有注释，改代码前先看那里的说明。）

## 3. 口径：什么算「一次访问」

这是最需要写清楚的一节 —— 数字长什么样，全由这张表决定。

### 3.1 算

| 情况 | 为什么算 |
| --- | --- |
| 打开/刷新任意页面（`Sec-Fetch-Dest: document`） | 就是他看了一个页面 |
| **站内无刷新切页（pjax）** | 本站点文章列表里点进文章走的是 pjax，不发整页导航。只看整页导航的话，「进来首页算 1 次、点开五篇文章算 0 次」，统计就废了。好在 pjax 自己会带 `X-PJAX: 1` 这个头，直接认它，**一行 pjax 代码都没改** |
| 浏览器走缓存协商、服务器回 `304` | 页面确实在他屏幕上渲染出来了 |
| 老浏览器（不发 `Sec-Fetch-*`）但 `Accept` 里有 `text/html` | 兜底，免得漏掉旧 Safari / App 内置浏览器 |

### 3.2 不算

| 情况 | 为什么不算 |
| --- | --- |
| 图片 / CSS / JS / 字体 / 音乐 | 一个人开一页会产生几十个这种请求，算进去数字毫无意义 |
| **鼠标悬停预取**（`X-PJAX-Prefetch`） | 只是鼠标从链接上路过，没人点 |
| **浏览器预取**（`Sec-Purpose: prefetch` 等） | 本站 `<head>` 里有 Speculation Rules 预取，不挡的话**扫一遍鼠标就能刷出十几次「访问」** |
| 搜索索引等前端 fetch（`/index.json`） | 是脚本在取数据，不是人在看页面 |
| `HEAD` 请求、非 `GET` | 不是人在浏览 |
| **307/301 跳转那一次** | 少写一个斜杠（`/posts/foo`）时资源服务器会跳一次，紧接着浏览器再请求一次带斜杠的地址 —— 两次都记就成了同一页算两遍 |
| **404 / 500** | 不是正常访问（爬虫扫 `/wp-login.php` 那种就落在这条，UA 漏掉它也拦得住） |
| 明显的爬虫 / 脚本 | 见下一节 |
| 直接粘 URL 打开 `/index.xml`、`/favicon.ico` | 不是「看了一个页面」 |

### 3.3 过滤了哪些机器人

按 User-Agent 里的**明显特征**过滤（不区分大小写），命中任一条就整条丢掉：

| 类别 | 特征 |
| --- | --- |
| 通用关键词 | `bot`、`crawl`、`spider`、`slurp`、`scrape` |
| 名字里不带上面几个词的 | `bingpreview`、`facebookexternalhit`、`bytespider`、`petalbot`、`ahrefs`、`semrush`、`mj12`、`dotbot`、`screaming frog`、`seznam`、`yandex` |
| 命令行 / 脚本 / HTTP 库 | `curl`、`wget`、`httpie`、`python`、`go-http-client`、`okhttp`、`axios`、`node-fetch`、`undici`、`libwww`、`winhttp`、`scrapy`、`postman`、`insomnia`、`powershell`、`restsharp` |
| 无头浏览器 / 监控探针 | `headless`、`phantomjs`、`puppeteer`、`playwright`、`selenium`、`lighthouse`、`pagespeed`、`pingdom`、`uptimerobot`、`statuscake`、`site24x7`、`datadog`、`newrelic`、`monitoring` |
| AI 抓取器 | `gptbot`、`claudebot`、`ccbot`、`perplexity`、`applebot`、`amazonbot` |
| **没有 User-Agent** | 真浏览器一定会带，不带的当爬虫 |

⚠️ **没过滤的**：把 UA 伪装成 Chrome 的爬虫（伪装了就认不出来 —— 想看真实占比只能另开 Cloudflare 的 Bot Management，那是付费功能）；
带「真人浏览器 UA + 真人行为」的采集器；以及名字里不带上面任何特征的冷门爬虫。
**漏掉的表现是数字偏高，不会漏掉真人。**

要加/删特征，改 `worker/index.mjs` 顶部的 `BOT_UA_MARKERS` 数组即可，不用动逻辑。

## 4. 记录了什么

一条记录（Analytics Engine 里的一个「数据点」）长这样。**字段顺序不能改** ——
Analytics Engine 是按位置存的，改了顺序老数据的含义就串了；要加字段只能往后追加。

| 列 | 内容 | 例子 |
| --- | --- | --- |
| `timestamp` | 时间（UTC，Analytics Engine 自动加） | `2026-10-11 03:20:11` |
| `index1` | **访客指纹**（当天去重用，见 §5） | `9f2a…`（32 位十六进制） |
| `blob1` | 页面路径（已归一化、去掉查询串） | `/posts/hello` |
| `blob2` | 国家（Cloudflare 免费给的两位码） | `CN` / `US` / 拿不到时 `XX` |
| `blob3` | 来源 | `direct` 直接打开 / `internal` 站内跳转 / `www.google.com` 这种**只有主机名** |
| `blob4` | 设备粗分类 | `desktop` / `mobile` / `tablet` |
| `blob5` | 载荷方式 | `load` 整页进入 / `pjax` 站内无刷新切页 |
| `double1` | 恒为 `1` | 查询时 `sum(double1)` 就是访问次数 |
| `_sample_interval` | 采样倍率（Analytics Engine 自动加） | 量小的时候恒为 `1` |

**路径归一化**：`/posts/foo/`、`/posts/foo`、`/posts/foo/index.html` 会并成 `/posts/foo`，
免得同一页在结果里散成三行。**查询串（`?a=b`）一律丢掉**（它会让基数爆炸，也可能带上别人的隐私参数）。

## 5. 隐私上做了什么

| 做法 | 为什么 |
| --- | --- |
| **不存 IP** | 只存 `IP + User-Agent + 当天盐值` 的 SHA-256 前 32 位 |
| **盐值每天换** | 盐里带上当天日期（UTC），昨天和今天的哈希**完全对不上** → 「同一天内去重」做得到，**跨天跟踪做不到** |
| 可选密钥 `VISIT_SALT` | 不配也能跑（那时的盐只剩日期）。配上以后，即使有人同时拿到这张表和这份源码，也没法靠穷举 IP 把哈希还原成某个人。配法见 §8.4 |
| 来源只留**主机名** | 不留完整网址：别人的搜索词、别的站的内部路径都在 URL 里，留了就是替别人泄露 |
| 不记城市/经纬度/邮编 | Cloudflare 其实免费给这些，但本站**只要国家** —— 粒度越细越接近「定位到人」 |
| 没有 Cookie、没有第三方 JS | **本套统计**在浏览器端一行代码都没加、不写任何 Cookie。⚠️ 但页面上确实有**一个**外链脚本 —— Cloudflare 自动注入的 Web Analytics beacon（**不是本站加的、仓库里也没有**，见 §1.1 与 [`技术总览.md`](技术总览.md) §1.3） |
| **不做公开的 `/stats/` 页面** | 那等于把你的访问数据公开给所有人 |

⚠️ 「一天」按 **UTC** 算（= 北京时间早上 8 点换日）。这么定是为了和 Analytics Engine 的
`timestamp`（也是 UTC）严格对齐，否则跨日那几小时的访客会被重复算两次。
想按北京时间换日的话，改 `worker/index.mjs` 里 `visitorHash()` 的 `day` 一行，
**但那之后查询也要跟着按 UTC+8 分组**，两边必须一起改。

### 7.3 现成的查询（粘到后台查询框或脚本里都能用）

```sql
-- ① 最近 7 天：访问次数 + 访客数
SELECT SUM(_sample_interval * double1) AS 访问次数,
       count(DISTINCT index1)          AS 访客数
FROM my_blog_pageviews
WHERE timestamp > NOW() - INTERVAL '7' DAY;

-- ② 最热的页面
SELECT blob1 AS 页面,
       SUM(_sample_interval * double1) AS 访问次数,
       count(DISTINCT index1)          AS 访客数
FROM my_blog_pageviews
WHERE timestamp > NOW() - INTERVAL '7' DAY
GROUP BY 页面 ORDER BY 访问次数 DESC LIMIT 25;

-- ③ 按天
SELECT toDate(timestamp) AS 日期,
       SUM(_sample_interval * double1) AS 访问次数,
       count(DISTINCT index1)          AS 访客数
FROM my_blog_pageviews
WHERE timestamp > NOW() - INTERVAL '30' DAY
GROUP BY 日期 ORDER BY 日期 DESC;
```

> `SUM(_sample_interval * double1)` 里那个 `_sample_interval` 不是多余写法：
> Analytics Engine 在数据量很大时会**采样**，不乘它数字会偏小。
> 现在本站的量根本采不到样（它恒为 1），但留着以后才不用回来改。
>
> **访客数为什么是 `count(DISTINCT index1)`**：`index1` 就是那个「当天换盐的访客指纹」，
> 所以它数出来的是「当天有多少个不同的人」，同一个人的多次访问只算一个。
>
> ⚠️ **列别名只能用英文**（实测踩过）：写成 `SELECT … AS 访问次数` 会被解析器直接拒掉 ——
> HTTP 422 `sql parser error: Expected an identifier after AS, found: 访`。
> 另外 `timestamp` 也**不要加别名**（`timestamp AS ts` 会报 `unable to find type of column`）。
> 想显示中文就在展示层翻，别写进 SQL。

### 7.4 怎么建一个**只读**令牌（要跑脚本才需要）

> ⚠️ 这一步只能你自己做，agent 没有你的账号权限，**也不该替你建凭据**。

1. 打开 <https://dash.cloudflare.com/profile/api-tokens>
2. **Create Token** → 拉到底选 **Create Custom Token**
3. 名字随便写，比如 `blog-stats-readonly`
4. **Permissions** 选：`Account` | `Account Analytics` | `Read`
   （⚠️ 只要 Read。**不要**给它 Workers Scripts 之类的写权限）
5. 可以顺手设个有效期（TTL）和 IP 限制
6. **Continue to summary → Create Token**，把令牌复制下来
7. 只在当前这个终端窗口里用，别写进任何文件、别提交：
   `$env:CLOUDFLARE_API_TOKEN = "刚复制的令牌"`

这个令牌**只能读统计，改不了站点、动不了任何配置**。想作废随时回那一页 Revoke。

## 8. 怎么改口径

| 想改什么 | 改哪 | 注意 |
| --- | --- | --- |
| 加/删爬虫特征 | `worker/index.mjs` 的 `BOT_UA_MARKERS` | 加一条子串即可，`bot` 这种宽词要小心误杀 |
| 「什么算一次访问」 | `worker/index.mjs` 的 `shouldCount()` / `isPageRequest()` | 唯一的判定入口，改完先跑 §10 的自测 |
| 连 404 也统计 | `shouldCount()` 里放开状态码判断 | 会开始把爬虫扫站的 404 算进来 |
| 来源记完整网址 | `referrerOf()` | ⚠️ 会带上别人的搜索词与内部路径，等于替别人泄露 |
| 多记城市 | `record()` 里加 `cf.city` 到 blobs | ⚠️ 粒度变细 = 更像「定位到人」，隐私上要自己想清楚 |
| 「一天」按北京时间 | `visitorHash()` 里的 `day` | ⚠️ 查询也要跟着按 UTC+8 分组，两边一起改 |
| 加字段 | `record()` 的 `blobs` 数组**末尾**追加 | ⚠️ 顺序不能插队，Analytics Engine 按位置存；同时在 §4 表格里登记 |

改完必须做两件事：**跑一遍 §10 的自测**，再**推上去让 Actions 重新部署**（改 `worker/` 下的文件同样要走部署才生效）。

## 9. 怎么关掉 / 怎么回滚

### 9.1 只想「暂时不统计」（最快，不用改代码）

在 Cloudflare 后台把数据集绑定挪走？—— **别这么干**，那会让 `env.VISITS` 变成 undefined。
最省事、最安全的做法是**回滚到部署统计之前的那个版本**（见 §9.3），这也是本站统计出任何问题时的第一选择。

### 9.2 想永久关掉（改代码）

按下面顺序删，每一步都仍然是一个**能正常访问的站点**：

1. 删 `wrangler.toml` 里的 `[[analytics_engine_datasets]]` 那三行 → 从此不再写数据；
2. 删 `wrangler.toml` 里的 `main = ...` 与 `[assets]` 下的 `binding`、`run_worker_first` 两行
   → 站**回到改动前的纯静态托管状态**（Worker 不再执行任何脚本）；
3. `worker/` 目录和 `tools/` 下那两个脚本可以留着不管（部署只上传 `public/`，它们不会被发出去）。

> ⚠️ **别只删第 2 步里的 `run_worker_first` 就以为关掉了** —— 那样 Worker 多半根本不会被执行，
> 看起来「统计没了」，实际上是把整段脚本变成了永远不会跑的死代码，以后想改口径会一头雾水。

### 9.3 线上出问题了：怎么一键退回上一个版本

Cloudflare 会保留每次部署的版本，**退回不用重新构建、不用改代码**：

1. 打开 Cloudflare 后台 → **Workers & Pages** → 点 **my-blog**
2. 选 **Deployments**（部署）标签页
3. 在列表里找到**上一次正常的版本**（加统计之前那一条）
4. 点它右侧的 **三个点 ⋯** → **Rollback**（回滚）
5. 立刻生效，域名上跑的就是旧版本了

已经写进去的统计数据**不受影响**（回滚不动绑定和数据）；最坏情况是那几分钟的数据白记了 —— 无所谓。

### 9.4 想彻底删掉数据

Analytics Engine 的数据**不用手动删、也没有删除入口**：**3 个月后自动过期消失**。

#### 顺带已经确认过的一件事：平台那套统计没被弄哑

`run_worker_first = true` 意味着**每个请求都先经过我们的 Worker**，
当初担心它会把 Cloudflare Web Analytics beacon 的上报端点 `/cdn-cgi/rum` 一起吞掉（回 404）。
2026-10-10 部署完实测：**没有这回事。**

- `GET /cdn-cgi/rum`（带 `Origin`/`Referer`）→ **405 + `Allow: POST, OPTIONS`**，由 Cloudflare 边缘直接回应；
- `POST /cdn-cgi/rum` 返回的 404 是 **Cloudflare 自己的**错误页，不是本站的 Hugo 404 页 —— 说明请求没进 Worker；
- `GET /cdn-cgi/trace`、`/cdn-cgi/speculation` 也都是 200。

**所以 `/cdn-cgi/*` 不需要排除，平台统计照常在收数。**
⚠️ 自己复验时记得带 `Origin`/`Referer`：不带的话连 Cloudflare 都回 404，会误判成「被 Worker 挡住了」。
详见 [`技术总览.md`](技术总览.md) §1.3。

## 11. 已知局限（诚实列出，免得以后拿数字当真）

1. **只会少算，不会虚高。** pjax 的悬停预取会提前把页面取回来，
   之后那一次点击是**从浏览器缓存里渲染的、根本不发请求**，这一次就统计不到。
   所以「访问次数」应读作「**真正到达服务器的页面请求数**」的下限，不是完整 PV。
2. **访客数是「人次」不是「人数」。** 同一个人换了网络（IP 变了）、换了浏览器、开了隐私模式，
   当天就会被算成两个人；同一台手机同一天用 4G 和 WiFi 各看一次，也可能是两个。
   ——这是「不存 IP、不留长期标识」必然的代价，**故意的**。
3. **3 个月就没了。** 想要更长的历史，得自己定期把结果导出存起来。
4. **`XX` 国家** 表示那次请求没拿到地理信息（本地开发、或极少数情况下 Cloudflare 没给）。
5. **数据点写入是「发出去就不管」的**：Cloudflare 文档说 `writeDataPoint()` 立即返回、
   后台批量写。所以**偶尔丢几条是可能的**，别把个位数的差异当回事。
6. 微信 / QQ / 各种 App 内置浏览器**不一定发 `Sec-Fetch-*`**，走的是 `Accept` 兜底那条路，
   归类可能不准（尤其设备类型）。
