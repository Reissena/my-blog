这些数字是怎么来的

篇文章
构建时数 content/posts/ 目录下的文章。和左栏目录里那个数字是同一个集合。
首歌
读歌单 data/music.yaml 的条数。音频文件在 Cloudflare R2 上，不在仓库里。
运行天数
从 hugo.toml 的 siteLaunchDate（{{ $up.since }}）算到今天， 与页脚状态栏那句「本站已稳定运行」用的是同一份算法。
页面访问
{{- if gt $visits 0 }} 来自本站自己的服务端统计（Cloudflare Analytics Engine）， 只数页面、不数图片和样式；同一个人的多次访问按同一份匿名指纹汇总。 这个数是最近一次成功查询的结果：部署时能查到就自动刷新， 查不到就沿用上一次的，所以它不是实时数字 —— 右下角标的「截至」就是那一次查询的日期； Analytics Engine 只保留 3 个月，所以「累计」指的是保留期内的总和。 {{- else }} 这一页这次没有显示访问次数 —— 它在构建时单独去查一次 Cloudflare，要仓库里配好只读凭据才查得到；查不到就整张卡片不显示 （不留空框、也不拿 0 充数），网站照常部署。 {{- end }}

这里只放汇总量。访问者层面的东西一个都没有： 没有单条访问记录、没有 IP、没有来源与设备、没有地理分布、也没有按天的时间曲线 —— 能反推到「某个人什么时候看了哪一页」的数，这一页一律不放。
